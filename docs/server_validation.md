# 서버 전환 검증 범위

검증일: 2026-10-25. 실제 결과 JSON: [수치 대조](server_parity_validation.json).

로컬 실제 추론 35개 사례가 통과했으며 최대 절대차는 0.0000095367431640625 mmol/g였습니다. 공개 변환 도구로 원래 비공개 체크포인트에서 ONNX를 다시 생성하여 파일 SHA-256이 기존 배포 대상과 일치함을 확인했습니다. [20개 구조 변환 검사](server_export_validation.json)

- 공개 자산 SHA-256, Python 구문, 출력 제거 notebook, 문서 링크를 검사합니다.
- 고정 train/validation/test 35,000/5,000/10,000개 ID가 서로 겹치지 않으며, 추가 10,000개 ID는 원래 50K 전체와 겹치지 않습니다. 추출 순서 해시도 검사합니다.
- 공개 CI는 가중치를 내려받지 않습니다. API 계약 검사에는 명시적인 FakePredictor를 사용하고, 별도로 실제 20개 CIF의 동결 전처리를 검사합니다.
- 비공개 모델을 사용하는 로컬 수치 검사는 기술자 변경 포함 35개 사례와 실제 CIF 업로드를 원래 PyTorch 출력과 대조합니다. 모델의 HTTP 다운로드 경로가 404인지도 검사합니다.
- 원래 전체 GPU 학습과 추가 10K 추론을 새로 수행한 검증은 아닙니다. Linux 클라우드 배포의 메모리·성능 및 실제 스마트폰은 별도 확인 대상입니다.
- 로컬 브라우저에서 20/20 순차 예측 완료, 중간 결과(#5) 다시 보기, CO₂/CH₄ 전환, 실제 CIF 업로드와 네 기술자 직접 입력을 확인했습니다. 별도 Netlify/API 도메인 조합은 아직 배포하지 않았습니다.

실행 명령과 환경은 [재현 문서](reproduction.md), 운영 제한은 [배포 문서](deployment.md)를 따릅니다. 공개 CI 성공과 비공개 모델 검증은 서로 다른 확인입니다.

## 2026-10-25 초기화 진단 보강

첫 Render 시도는 모델 준비 상태 검사 503이 지속되어 배포 시간 초과로 끝났습니다. 원인이 해결되었다고 주장하지 않습니다. 단계별 로그·초기화 경과 시간·스레드 생존 여부·Linux 메모리 진단을 추가했으며, 네트워크 인증 정보와 원본 예외 메시지를 출력하지 않습니다. ONNX 연산 옵션과 가중치는 그대로입니다.

추가 테스트는 파일 없음, 해시 불일치, 로딩 중 503/완료 후 200 전환, 초기화 예외에서 비밀값 미노출, 중복 초기화 방지 및 다운로드 검증을 확인합니다. Linux CI에서는 실제 Gunicorn 워커를 실행하여 가중치가 없을 때 안전한 실패 상태를 보고하는지도 검사합니다. 이 테스트가 실제 클라우드 모델 로딩 성공을 대신하지는 않습니다.

## 확인된 부모/워커 상태 불일치 수정

후속 Render 로그에서 모델을 초기화한 PID 57은 5.204초 만에 준비되었지만, 워커 PID 62의 로더는 살아 있지 않았고 복제 시점의 준비 전 상태에 머물렀습니다. import 시점의 백그라운드 초기화를 제거하고 워커 생성 후에만 초기화하도록 수정했습니다. 토큰·다운로드 및 예측 계산의 문제가 아니었습니다.

회귀 검사는 부모의 잠긴 초기화 락·로딩 상태가 워커에 재사용되지 않는지 확인합니다. Linux CI에서는 임시 비학습 Identity ONNX 그래프로 실제 네이티브 로딩을 수행하고, 일반 시작과 preloaded 시작 모두 모델 PID가 요청 처리 워커 PID와 같은지 확인합니다. 훅을 끈 첫 요청 시작 경로도 검사하며, 합성 그래프 검사는 연구 모델 정확도 검증과 구분합니다.
